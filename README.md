# Project Handbook

**给出代码、文档和一个问题，得到一份可离线打开的 HTML 流程图。**

不用先知道函数名。先看整体顺序，再沿“是 / 否”分支理解处理过程；点击节点查看公式、细节与依据，最后跟着例子走一遍。

## 快速上手

1. 下载本项目，将 `project-handbook` 文件夹放到你使用的助手的 skills 目录。
2. 在支持本地 skills 的助手中提供可读取的代码和文档目录。
3. 直接提出问题，例如：

```text
使用 project-handbook。
我是新人，想知道订单支付是怎样完成的。
客户端目录：D:/demo/client
服务端目录：D:/demo/server
文档目录：D:/demo/docs

请输出一份 HTML 流程图：
- 先说明必要的框架与整体顺序。
- 不同入口分开，公共处理合并展示。
- 判断标明是/否，说明跳过、结束和回到主线的情况。
- 点开节点能看字段、公式和代码依据。
- 给出正常、边界、异常例子。
```

目录缺一项也可以使用。助手会先读取现有材料，把无法确认的细节标在相关节点中。目录应能被助手访问；生成的 HTML 本身不提供目录上传功能。

## 在本机运行示例

需要 Python 3.10 或更高版本，无需安装 Python 第三方依赖：

```sh
python project-handbook/scripts/build_flow.py project-handbook/assets/flow.example.json payment-demo
```

双击 `payment-demo/handbook.html`。文件内含图、样式、交互和来源摘录，不需要启动服务，也不需要配置模型。

输出目录必须是新目录。再次生成时换一个目录名，避免覆盖已有成果。

## 继续追问或调整

把新问题交给助手，例如：

```text
把支付失败和重复通知的处理补进图里。
把“金额计算”拆开，增加优惠券和取整的具体例子。
这个字段的含义不清楚，请沿调用链核对后更新节点。
```

助手负责阅读代码、核对业务含义；生成脚本负责把整理后的流程渲染成 HTML。扫描目录并不等于已经理解全部业务。

需要手动调整流程数据时，参考 [流程字段与编写说明](project-handbook/references/flow.md) 和 [可运行示例](project-handbook/assets/flow.example.json)。
