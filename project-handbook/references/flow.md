# 流程图交付

默认交付一张完整、可缩放和拖动的画布。入口、条件分支、公共步骤和结果都在图中，不通过页签隐藏后半段。细节、公式、例子和证据放在相关节点的详情里。

以 `assets/flow.example.json` 为可运行示例。

- `title/summary`：直接回答用户问题，交代必要前提。读者多是产品、运营，用业务语言写，少用代码名；代码名放进 `lines` 或 `detail`。
- `project`：读过的资料文件夹绝对路径（字符串或列表）。只留在本机的 flow.json / flow-data.js 里，供之后回答页面里的提问时查资料；不会写进网页，也不会进分享副本。
- `graphs` 仅为作者组织流程段的数据结构，所有流程段同时显示。
- 每段含 `id/title/source/nodes/edges`。`source` 是这段默认的来源条目。`title` 会显示在图上这一段的左上角；有多段时，画布上方还会出现「跳到」按钮。
- 节点含 `id/title/row/col/kind/lines/detail`；段内行从 0 开始，列 0～3；类型为 process、decision、switch、terminal、merge。
- 节点可选 `sources: ["来源id", …]`：这一步的依据和所在段不同时就写上，比如公式在另一个文件、数值在配置表。点开节点、追问这个节点时只用这里列出的来源；不写就用段的 `source`。
- 可选 `position: {row, col}` 定义流程段在全局画布的位置；不写时依次向下排。可用列偏移把多入口并排，公共段只画一次。
- 段内连线含 `a/b/label/route`。route 可省略，也可用 outer 或 bypass。
- 分支：`decision` 恰有“是”“否”两条出口；三种及以上结果（如 普攻 / 技能 / Buff）用 `switch`，2～6 条出口，每条写不同的标签。不要把多路分支拆成一串是否判断。
- ID 以字母开头，只用字母、数字、`-`、`_`，全图唯一。页面自己占用了一些 ID（如 `source`、`next`、`detail`、`search`、`canvas`），用了会被拒绝并提示换名。
- 顶层 `connections` 明确给出跨段连线，含 `a/b/label`，引用实际节点 ID。不要由段顺序、名字或 `common` 字段猜测业务连线。条件和触发事件写在线上。
- `sources` 含 id、locator、excerpt。每个节点保留所属来源；不同段的节点不能错误共用第一段的证据。
- `examples` 含 title、provenance、input、trace（字符串数组）、result。区分演示与实测。
- 例子尽量写 `path`：按顺序列出这个例子经过的节点 ID，每相邻两个必须有一条已画出的连线（段内连线或 `connections`），中间节点不能跳过。页面上会出现「在图上看这条路线」，按顺序给节点编号并淡化其他部分。例子只讲某一段时，`path` 从那一段开始即可。

生成：有 Python 时用 `python -X utf8 scripts/build_flow.py flow.json NEW_OUTPUT`，输出目录必须不存在；校验失败时，报错会写明位置（如 `graphs[0].nodes[3] (crit)`）和改法。没有 Python 时，把 `assets/viewer/handbook.html` 原样复制进新目录，再写 `flow-data.js`（`window.HANDBOOK_DATA = ` + JSON + `;`）；页面打开时按同样的规则检查，出错会显示同样的报错和「复制给 AI」按钮。

布局使用向下的主线、同排向右的判断侧线、侧线向下汇合。`switch` 的各个出口放在它下一行的不同列（0、1、2…），每条出口的标签会画在各自那段竖线旁边。直线被节点遮挡时，渲染器会尝试沿网格行间和列间的空白绕行；不能把不同入口画成经过彼此。需要循环时画明确的独立说明节点，当前直角路由不支持任意回环。较复杂的多列图必须检查每条连线避让与标签可读性，不能仅凭结构验证宣称布局正确。

浏览器验收：首屏按宽度显示、从第一步开始；所有节点无需切换就存在；多段时每段标题和「跳到」可用；跨段箭头完整；全图、缩放、拖动、搜索定位有效；每个节点显示正确依据，详情里的「从这里来 / 接下来」与连线一致；例子路线编号顺序正确；移动端仅画布滚动；无外部请求。数值例子、条件、互斥、覆盖和执行顺序仍需对照源码或文档复核。

README 面向直接使用：下载 skill、在 WorkBuddy 或 Codex 中调用、提供问题和目录、打开 HTML。不要要求用户手写流程数据或运行构建命令。不要附加制作过程、改动总结等与解答无关的板块。发布只用合成或明确获准公开的数据。

网页内追问默认交给生成手册的 AI：页面复制问题，读者粘贴回对话，按 [answers.md](answers.md) 回答并存回 `answers.js`。在 Codex 里还可按 [flow-qa.md](flow-qa.md) 启动本地连接，在页面里直接看到回答。分享副本只能阅读。
